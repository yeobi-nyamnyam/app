## 서버(apps/server) 담당 매핑

`apps/server`는 별도 담당자 없이 **각 기능 담당자가 자기 도메인의 서버 라우터/프록시까지 직접 개발**합니다
(`docs/api-server-boundaries.md` 기준). Express 초기 스캐폴딩(공통 미들웨어, 인증 미들웨어, 에러 핸들링 등)만
세션 초반에 한 번 같이 세팅하고, 이후는 아래처럼 나뉩니다.

| 서버 도메인                                                             | 담당자 | 비고                                                                                                                                                                  |
| ----------------------------------------------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AI 채팅 LLM 프록시(C1, C2) + SSE 스트리밍                               | 초연   | `chat_messages` 기록, 파싱 결과 검증 후 반환                                                                                                                          |
| TourAPI·착한가격업소·네이버 Geocoding + `restaurants` 24시간 배치(F3-5) | 희정   | `restaurants` 배치는 `recommend` 담당자 혼자 시간 내 끝내기 빠듯해서, 배치 스크립트 자체는 세션 초반에 팀 전체/서버 세팅과 묶어 처리하는 걸 권장 (아래 참고)          |
| 클로바 리시트 OCR + 네이버 지도 검색(F6-10, 매장명 자동완성)            | 수진   | OCR은 Storage 업로드 → 서버 → OCR 호출. F6-10 결과 좌표는 `meal_logs.store_latitude/longitude`에 채움                                                                 |
| 여행 완료 시 배지/포인트 일괄 계산(G0~G17, L0~L4)                       | 수진   | `trip-complete`(F7) 트리거에 묶여 있어 서버 로직도 수진이 처리. `badges` 화면도 수진 담당(재배정)이라 서버·클라이언트 조율 불필요                                     |

## 배정 시 참고

- **핵심(우선순위 최고)** 기능: F3-3(추천 기준 산정, 희정), C2(자연어 파싱, 초연), F6-4(캐스케이드 확정, 수진) — 예산 재계산과 직결. F6-4(수진)는 결국 초연의 예산 캐스케이드 로직(§1~2)에 의존하니 초연이 세션 초반에 로직 문서화를 먼저 끝내는 게 우선 (F4는 초연이 F2와 함께 담당해 별도 조율 불필요)
- **필수** 기능부터 먼저 배정하고, **선택** 기능(G, L, M, D 일부)은 시간 남으면 진행
- `recommend`(희정)과 `chat`(초연)을 서로 다른 사람에게 분산해 서버 프록시 설계 부담을 나눔 — 세 사람이 동시에 작업 가능하도록 초연(인증·여행생성·예산·예산수정·채팅) / 희정(추천·마이페이지 M2) / 수진(기록·일기·여행완료·배지·캐릭터·마이페이지 M0/M1)으로 재배정
- **F3-5 배치 스크립트**(착한가격업소 전량 수집+Geocoding+upsert)는 `recommend` 담당자(희정) 혼자 시간 내 끝내기엔 분량이 있어서, 세션 초반에 팀 전체가 같이 붙어서 처리하고 이후 화면/서버 라우터 작업은 희정이 이어가는 방식을 제안 (`business-logic-notes.md` §8, 결정이 필요한 것 항목 참고)
- **F4(예산수정)와 F2(예산산정)는 모두 초연**이 담당해 캐스케이드 로직(§1~2) 문서화와 F4 착수 사이의 인원 간 조율은 필요 없음

## 재배정 (2026-09-02)

킥오프 시점 배정 이후 다음 두 건이 재배정됨:

- **M2(방문 매장 지도)**: 수진 → 희정. 원래는 `record`(수진)가 F6-10에서 채우는
  `meal_logs.store_latitude/longitude`를 그대로 소비하도록 동일인으로 묶었지만,
  희정이 맡기로 함에 따라 이제 스키마를 채우는 사람(수진)과 쓰는 사람(희정)이
  달라져 사전 합의가 필요해짐
- **배지(G0~G17) UI**: 희정 → 수진. 배지 판정 서버 로직(여행 완료 시 배지/포인트
  일괄 계산)은 원래도 수진 담당이었어서, UI까지 같이 맡으면 서버·클라이언트
  담당자가 일치해 스키마 조율 부담이 사라짐
